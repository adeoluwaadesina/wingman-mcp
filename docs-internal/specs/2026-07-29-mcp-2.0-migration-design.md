# Migrate to mcp 2.0.0 (FastMCP -> MCPServer, stateless HTTP)

## Problem

The `mcp` Python SDK shipped a breaking major version, 2.0.0, implementing
the new MCP 2026-07-28 spec (stateless protocol core, Tasks extension,
hardened OAuth, MCP Apps folded into a formal extensions framework).
2.0.0 removes `mcp.server.fastmcp.FastMCP` entirely, replacing it with
`mcp.server.mcpserver.MCPServer`. Wingman's `pyproject.toml` had an
unpinned `mcp>=1.2.0`, so a fresh install (Render redeploys on every
push) started resolving to 2.0.0 and crashed both the local and Cloud
servers with `ModuleNotFoundError: No module named 'mcp.server.fastmcp'`.

An immediate fix (`mcp>=1.2.0,<2.0.0`, commit `1b095e3`) is already
shipped and stable. This spec covers the follow-up: actually migrating
onto `MCPServer` and opting into the new stateless HTTP model, rather
than staying pinned to the deprecated 1.x line indefinitely.

## Research findings (verified against the real 2.0.0 package)

- `MCPServer.__init__` keeps the same `name`, `icons`, `website_url`,
  `instructions` kwargs Wingman already passes to `FastMCP`. No change
  needed there beyond the class name.
- `.tool()` and `.resource()` decorators keep the same signatures
  (`name`, `title`, `description`, `annotations`, `icons`, `meta`,
  `mime_type` etc.) that `server.py` and `server_http.py` already use.
- `mcp.types` (`CallToolResult`, `TextContent`, `ToolAnnotations`)
  imports are unchanged.
- `MCPServer.run()` (stdio default) is unchanged in signature and
  behavior — the local server's `main()` needs no logic changes.
- The one real API change: `transport_security` moves out of the
  `MCPServer(...)` constructor and into `streamable_http_app(...)`
  (and `run_streamable_http_async(...)`), which also gains a new
  `stateless_http: bool = False` parameter. Setting it `True` is the
  actual opt-in to the new spec's stateless model.
- Wingman's own auth code (`AuthMiddleware.dispatch` in
  `cloud/server_http.py`) already reads identity fresh off each
  incoming HTTP request via a context var (`identity.set_current_user`
  / `identity.reset`), and never relies on state persisting across
  requests via the MCP session. So enabling `stateless_http=True`
  should not require changes to Wingman's own request-handling logic —
  only to how `build_app()` constructs the `streamable_http_app()`.
- No test file imports `FastMCP` directly (`tests/test_server.py` has
  one comment mentioning it, no import), so the rename itself has
  minimal direct test blast radius. The real proof is the existing
  live smoke test, `tests/cloud/test_smoke_http.py`, which drives the
  full Cloud app over real HTTP with a real MCP client against a real
  Postgres DB (gated on `WINGMAN_TEST_DSN`; currently skipped locally
  because that env var isn't set). It uses a stub token verifier
  (no real WorkOS calls) and truncates its own tables, so it's safe to
  run against a scratch/test database.

## Change

Three files change:

1. **`pyproject.toml`**: `"mcp>=1.2.0,<2.0.0"` -> `"mcp>=2.0.0,<3.0.0"`.
2. **`src/wingman/server.py`** (local, stdio): replace the
   `from mcp.server.fastmcp import FastMCP` import with
   `from mcp.server.mcpserver import MCPServer`, and rename every
   `FastMCP` reference (the `build_server() -> FastMCP` return type
   annotation and the `FastMCP(...)` instantiation) to `MCPServer`.
   No other logic changes — stdio transport has no session/statelessness
   concept to migrate.
3. **`src/wingman/cloud/server_http.py`** (Cloud, streamable-HTTP):
   - Same import/rename as above, applied to `build_mcp(cfg) -> FastMCP`
     (becomes `-> MCPServer`) and its `FastMCP(...)` instantiation.
   - In `build_mcp()`, remove the `transport_security=TransportSecuritySettings(...)`
     argument from the `MCPServer(...)` constructor call (that kwarg no
     longer exists there in 2.0.0).
   - In `build_app()`, change
     `mcp_app = mcp.streamable_http_app()` to pass both the transport
     security settings (moved here) and the new stateless flag:
     `mcp_app = mcp.streamable_http_app(transport_security=<settings>, stateless_http=True)`.
     The `TransportSecuritySettings(...)` construction itself (DNS
     rebinding protection, `allowed_hosts`, `allowed_origins`) is
     unchanged in shape — only *where* it's passed moves.

No changes to `store_pg.py`, `observability.py`, `cloud/__main__.py`,
`auth.py`, `hardening.py`, or any tool-registration logic. No changes
to the local SQLite storage layer, the panel UI, or any test file
(existing tests should pass unmodified against the migrated code; the
smoke test simply stops being skipped once `WINGMAN_TEST_DSN` is set).

## Testing

- Full existing test suite (`pytest`, currently 89 passed / 29 skipped)
  must still pass after the migration, run against the real installed
  `mcp==2.0.0` (not mocked).
- The Cloud HTTP smoke test (`tests/cloud/test_smoke_http.py`) must be
  run for real, not skipped, against the user's separate scratch/test
  Neon database (provided out-of-band, not the production database) by
  setting `WINGMAN_TEST_DSN` for that run. This is the only test that
  actually proves the stateless streamable-HTTP transport still carries
  identity/isolation correctly end-to-end.
- Manual local smoke: run the local (stdio) server via
  `python -m wingman` and confirm it starts without error (stdio has no
  automated end-to-end test today, per existing test suite structure).

## Deployment

After tests pass locally, push to `dev` (Render auto-deploys from
`dev` on every commit) and verify:
- The service boots without the `ModuleNotFoundError` or any new
  startup error.
- `GET /healthz` returns 200.
- A real connect-and-use pass from an actual MCP client (Claude or
  ChatGPT) against the live Cloud URL, confirming tool calls still
  work end-to-end in production, not just in the smoke test.

## Out of scope

- Adopting the Tasks extension (`tasks/get`, `tasks/update`, etc.) for
  the "Run task" feature — a real potential future use, but a separate
  feature project, not part of this dependency migration.
- Enterprise Managed Authorization — not relevant to Wingman's current
  single-tenant-per-user auth model.
- Any change to WorkOS AuthKit configuration, OAuth flow, or token
  verification logic.
- Republishing to PyPI (the 0.3.1 bump for the local package) — the
  user has said to wait on that; it is a separate, later step after
  this migration and the LinkedIn post.

## Success criteria

- `pyproject.toml` requires `mcp>=2.0.0,<3.0.0`.
- Both `server.py` and `cloud/server_http.py` import `MCPServer` from
  `mcp.server.mcpserver`; no remaining reference to `FastMCP` or
  `mcp.server.fastmcp` anywhere in `src/`.
- Full test suite green, including the live smoke test run against the
  scratch database (not skipped).
- Live Render deployment on `dev` boots cleanly and serves a real
  connect-and-use pass from an actual MCP client.
